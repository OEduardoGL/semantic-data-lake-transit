# Prompt 2 - ML com Foco Gerencial (v1)

## Objetivo
Gerar codigo Python para treinar e avaliar um pipeline simples de Machine Learning sobre a `final_table` enriquecida de transporte, seguindo o fluxo:
`FinalTable -> ML simples -> metricas -> agregados gerenciais`.

Escopo desta versao:
- suportar comparacao entre 2 LLMs:
  - OpenAI `gpt-4o`;
  - `Llama 3.3 70B Instruct`;
- validar a utilidade pratica da `final_table` como base de ML;
- gerar saidas uteis para tomada de decisao e posterior publicacao no Neo4j.

## Objetivo duplo obrigatorio
O codigo gerado deve atender a dois objetivos ao mesmo tempo:

1. Validar tecnicamente a `final_table`
- confirmar que as features e o target permitem treino e avaliacao consistentes;
- treinar e medir um modelo simples, reproduzivel e explicavel.

2. Gerar valor gerencial
- produzir previsoes e agregados que permitam responder perguntas como:
  - quais linhas tendem a apresentar maior atraso previsto;
  - quais faixas horarias sao mais criticas;
  - quais veiculos apresentam maior instabilidade operacional.

## Contexto dos dados (Gold)
A `final_table` esta pronta e validada em `s3a://transport/gold/final_table`.

### Colunas disponiveis
Chaves e tempo:
- `event_dt` (date)
- `janela_5min` (timestamp)
- `cod_linha` (int)
- `cod_veiculo` (int)
- `id_empresa` (int)
- `viagem_sentido` (string)

Contexto espacial e operacional:
- `latitude_media` (double)
- `longitude_media` (double)
- `velocidade_media` (double)
- `gps_invalid_pct` (double)
- `qtd_eventos_gps` (bigint)
- `qtd_eventos_stop` (bigint)
- `max_satelites` (int)

Metricas de headway e target:
- `headway_observado_min` (double)
- `headway_referencia_min` (double)
- `atraso_aproximado_min` (double)

### Qualidade da Gold validada
- `row_count`: 375099
- `null_target_pct`: 0.1245%
- target_quality_status: `ok (<= 10%)`

## Definicao fechada do target
Usar obrigatoriamente como target principal:
- `atraso_aproximado_min`

Definicao do target:
- `atraso_aproximado_min = max(0, headway_observado_min - headway_referencia_min)`

## Requisitos do pipeline de ML
O codigo deve implementar um pipeline simples, reproduzivel e explicavel.

### Requisitos obrigatorios
1. Ler a `final_table` como DataFrame Pandas ou Spark, mas o pipeline final de treino pode ser feito com `pandas` + `scikit-learn` apos amostragem/controlada conversao se necessario.
2. Fazer limpeza minima segura:
- tratar nulos remanescentes;
- nao descartar colunas importantes sem justificativa;
- preservar o target e as chaves necessarias para agregacao posterior.
3. Gerar features temporais a partir de `janela_5min` quando fizer sentido, por exemplo:
- hora
- minuto
- dia da semana
4. Tratar colunas categoricas de forma simples e reproduzivel.
5. Treinar um modelo baseline simples e um modelo principal simples.
6. Avaliar em split temporal, sem embaralhar aleatoriamente as linhas.

## Baseline obrigatorio
Incluir obrigatoriamente um baseline ingenuo:
- mediana historica de `atraso_aproximado_min` por `cod_linha` + `faixa_horaria`

Esse baseline deve ser comparado com o modelo principal.

## Split temporal obrigatorio
Usar split temporal explicito, por exemplo:
- treino: inicio ate ~70%
- validacao: ~15%
- teste: ~15%

Regras:
- ordenar por tempo;
- nao embaralhar (`shuffle=False` conceitualmente);
- evitar vazamento temporal.

## Metricas obrigatorias
Calcular obrigatoriamente no conjunto de teste:
- `MAE`
- `RMSE`
- `MAPE`

Tambem reportar comparacao contra o baseline.

## Saidas gerenciais obrigatorias
O codigo deve gerar pelo menos estes artefatos tabulares:
1. previsoes por registro ou janela com colunas minimas:
- `event_dt`
- `janela_5min`
- `cod_linha`
- `cod_veiculo`
- `y_true`
- `y_pred`

2. agregado por linha/faixa horaria com colunas minimas:
- `cod_linha`
- `faixa_horaria`
- `avg_pred_atraso_aproximado_min`
- `avg_real_atraso_aproximado_min`
- `n_registros`

3. agregado por veiculo/dia com colunas minimas:
- `event_dt`
- `cod_veiculo`
- `avg_pred_atraso_aproximado_min`
- `avg_real_atraso_aproximado_min`
- `n_registros`

Esses agregados devem ser pensados para posterior uso no Neo4j.

### Formato de export para Neo4j
Os agregados devem ser exportaveis em formato tabular simples, preferencialmente:
- `CSV` para inspeção e carga direta
- `Parquet` quando o volume for maior ou a escrita intermediaria exigir compactacao

Nomear explicitamente os DataFrames/artefatos produzidos, por exemplo:
- `predictions_df`
- `line_hour_metrics_df`
- `vehicle_day_metrics_df`
